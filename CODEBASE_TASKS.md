# Предложенные задачи по улучшению кодовой базы

## 1) Исправление опечатки
**Тип:** typo fix  
**Задача:** Переименовать поля `acivisDateRu` / `acivisDateKz` в `acivsDateRu` / `acivsDateKz` для единообразия с термином «АЦИВС» в остальных местах кода.  
**Почему это проблема:** Сейчас в объекте `DATA` используется написание `acivis...`, тогда как во всех текстах и названиях переменных/файлов используется «ACIVS/АЦИВС». Это повышает риск ошибок при рефакторинге и поиске по коду.  
**Где видно:** `skills/dkt-letters/scripts/generate_letter_kn.js` (`DATA.acivisDateRu`, `DATA.acivisDateKz` и их использование).  
**Критерий готовности:** Переименованные ключи и все ссылки на них обновлены; генерация документа проходит без ошибок.

## 2) Исправление ошибки
**Тип:** bug fix  
**Задача:** Добавить явную валидацию входных файлов (`logoPath`, шаблон DOCX) и человекочитаемые сообщения об ошибках до начала генерации документа.  
**Почему это проблема:** Скрипт читает логотип напрямую через `fs.readFileSync(DATA.logoPath)` без предварительной проверки существования файла и валидности пути, что приводит к немедленному падению Node.js с системной ошибкой `ENOENT`.  
**Где видно:** `skills/dkt-letters/scripts/generate_letter_kn.js` (чтение `logoPath`), `skills/dkt-letters/scripts/gen_acivs_notice.py` (поиск шаблона и жесткая зависимость от структуры `paragraphs` по индексам).  
**Критерий готовности:** При отсутствующем файле пользователь получает понятную ошибку с подсказкой по исправлению; при корректных файлах скрипт работает как раньше.

## 3) Исправление комментария/документации
**Тип:** docs/comment mismatch  
**Задача:** Обновить комментарии «Запуск» и примеры путей в `generate_letter_kn.js`, чтобы они были переносимыми (без привязки к конкретной сессии `/sessions/jolly-magical-wright/...`).  
**Почему это проблема:** Текущие комментарии и пример `outputPath` привязаны к одному окружению и быстро устаревают; новый пользователь не сможет повторить запуск «как написано».  
**Где видно:** `skills/dkt-letters/scripts/generate_letter_kn.js` (блок комментариев в начале файла и пример `outputPath`).  
**Критерий готовности:** Инструкция запуска и примеры путей универсальны (например, через относительные пути/переменные окружения), шаги воспроизводимы в любом рабочем каталоге.

## 4) Улучшение теста
**Тип:** test improvement  
**Задача:** Добавить smoke/integration тест для генераторов писем: запуск скрипта на минимальном фикстурном наборе данных и проверка, что выходной `.docx` создан и содержит ожидаемые ключевые фразы.  
**Почему это важно:** В репозитории нет автоматической проверки генераторов; ошибки в шаблонах/полях проявляются только вручную при запуске.  
**Где применить:** Для `skills/dkt-letters/scripts/generate_letter_kn.js` (и аналогично для `gen_acivs_notice.py`).  
**Критерий готовности:** Тест запускается одной командой в CI/локально и падает при нарушении структуры документа или отсутствии обязательных данных.
