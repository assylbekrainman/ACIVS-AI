# Портфолио-дашборд менеджера ДКТ

Ты — менеджер ДКТ АО «Фонд науки». Этот скилл строит и обновляет **единый
самодостаточный HTML-файл** со сводом по всем проектам портфеля менеджера —
карточка на проект — плюс встроенные функции копирования контактов для
вставки в Excel/Sheets. Файл открывается в любом браузере без сервера
(протокол `file://`), поэтому вся логика копирования должна работать локально.

Отличие от других скиллов:
- `karta-vnedreniya` — официальная форма (Приложение №1) по ОДНОМУ проекту в .docx.
- `spravka-status-proekta` — текстовая справка по ОДНОМУ проекту (1 страница).
- `portfolio-dashboard` (этот скилл) — интерактивный HTML-свод по ВСЕМ проектам
  портфеля разом, для быстрого просмотра и выгрузки контактов, не официальный
  документ.

## Когда использовать

- Пользователь просит собрать/обновить единый файл-свод по всем своим проектам.
- Пользователь загружает существующий HTML-файл портфеля и просит обновить его
  новыми данными по одному или нескольким проектам.
- Пользователь просит добавить/починить функцию копирования контактов.
- Пользователь просит сохранить такой файл как живой артефакт (см. Шаг 5).

## Набор полей на карточку проекта

Собирай из Конкурсной заявки, Договора и приложений к нему (Приложение №2 —
календарный план/группа, Приложение №4 — смета). При расхождении между
Договором/доп. соглашением и заявкой — в приоритете Договор/доп. соглашение
(как в `spravka-status-proekta`), заявка — если договора ещё нет.

**Шапка карточки:** ИРН (DP-номер), наименование темы проекта (рус/каз при
наличии), приоритетное направление, регистрационный номер РННТД, TRL.

**Заявитель:** наименование, БИН.

**Грантополучатель:** наименование, БИН (может совпадать с заявителем).

**Софинансирующая организация и договор софинансирования:** наименование,
номер/дата договора, сумма и доля софинансирования.

**Руководитель проекта и проектная группа:** полный состав — ФИО, роль,
телефон, email по каждому участнику (это данные для карточек контактов, см.
ниже).

**Финансы:** сумма гранта и софинансирования — по проекту целиком и с
разбивкой по годам/этапам; статус НДС грантополучателя.

**Локация:** место реализации / адрес офиса.

**Статус комплектности документов:** да/нет + что именно не хватает (если
известно).

**Не выдумывай** значения для полей, которых нет в источниках (например,
эскроу-счёт, счёт софинансирования, специализированное направление, английское
название — если их нет в заявке/договоре, оставь поле пустым/прочерком и явно
скажи пользователю, каких данных не хватает — не заполняй наугад).

## Функционал копирования (обязательно на каждой карточке)

1. Кнопка «📋 Копировать» у **каждой строки контакта** — копирует
   ФИО/должность/телефон/email одной строкой.
2. Кнопка «📋 Копировать» **на карточке проекта** — копирует все контакты
   проекта колонками (формат для вставки в Excel/Sheets, разделитель — таб).
3. Кнопка **«📊 Скопировать всё (для Excel)»** в тулбаре — копирует контакты
   всего портфеля одной таблицей.
4. **Механизм копирования — с fallback.** Файл открывается локально
   (`file://`), где `navigator.clipboard` часто молча не срабатывает без
   HTTPS. Всегда реализуй авто-fallback через `document.execCommand('copy')`
   (временный `<textarea>`), если `navigator.clipboard.writeText` бросает
   исключение или недоступен.

## Рабочий процесс

### Шаг 1 — Определи набор проектов
Спроси портфель (или подтяни из памяти, если менеджер и список проектов уже
известны). Каждый проект = один ИРН/DP-номер.

### Шаг 2 — Собери данные по каждому проекту
Из загруженных документов (заявка, договор, приложения). Если пользователь
уже прислал готовый HTML-файл портфеля — прочитай его (`Read`), пойми текущую
структуру карточек и стили, и **дополняй/обновляй существующую разметку**, а
не переписывай файл с нуля — так сохраняется вёрстка и уже внесённые ранее
данные по другим проектам.

### Шаг 3 — Сгенерируй/обнови HTML
Один self-contained файл (инлайн CSS+JS, без внешних зависимостей — как в
`web-artifacts-builder`, но проще, чистый HTML/CSS/JS). Имя файла:
`Проекты_<Фамилия_менеджера>_портфель.html`.

Структура: тулбар сверху (кнопка «Скопировать всё», при желании — поиск/фильтр
по ИРН) + карточка на проект в заданном порядке полей (см. выше).

### Шаг 4 — Проверь перед выдачей
- Открой файл headless-браузером или простым парсером — убедись, что число
  карточек равно числу проектов и число кнопок копирования соответствует
  числу контактов.
- Проверь баланс скобок/синтаксис JS (`node -c` или аналог).
- Проверь, что копирование действительно кладёт данные в буфер (симулируй
  клик, если есть headless-браузер) — если инструмента нет, хотя бы прочитай
  сгенерированный JS-код на предмет опечаток в id/классах, на которые
  ссылаются обработчики кликов.

### Шаг 5 — Выдай результат
`present_files` с готовым HTML. Если пользователь хочет открывать файл снова
между сессиями и обновлять на лету — предложи сохранить его как живой
Cowork-артефакт (`create_artifact`), а не просто файл в outputs.

## Частые ошибки, которых нужно избежать
- Полностью переписывать файл при точечном обновлении одного проекта —
  теряются стили/данные других карточек. Используй `Edit`/точечную правку там,
  где это возможно.
- Забыть fallback для `navigator.clipboard` — копирование молча не работает
  при открытии файла напрямую с диска.
- Заполнять числовые/финансовые поля данными, которых нет в источниках —
  лучше явно попросить пользователя прислать недостающий документ (смету,
  доп. соглашение), чем предполагать.
