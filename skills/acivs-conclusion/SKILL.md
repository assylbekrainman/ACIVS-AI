## СТРУКТУРА ЗАКЛЮЧЕНИЯ (эталон)

### ЗАГОЛОВОК

Одинаковый для промежуточного и итогового отчёта — **НИКАКОЙ шапки «Утверждено Решением Правления АО «Фонд науки»...» НЕТ вообще**, ни для промежуточного, ни для итогового отчёта. Реальный подписанный эталон (DP21681706, даже с текстом «предоставлен итоговый (заключительный) отчёт» внутри Раздела 5) не содержит этот блок. Документ начинается сразу с заголовка:

```
ЗАКЛЮЧЕНИЕ АНАЛИЗА ЦЕЛЕВОГО ИСПОЛЬЗОВАНИЯ ВЫДЕЛЕННЫХ СРЕДСТВ
ПО ПРОМЕЖУТОЧНОМУ ОТЧЕТУ ЗА [N] ЭТАП          (или: ПО ИТОГОВОМУ (ЗАКЛЮЧИТЕЛЬНОМУ) ОТЧЕТУ ЗА [N] ЭТАП — для итогового)

г. Астана                    «___» __________ 202__ г.
```

Заголовок документа (оба абзаца) — 14pt **bold**, по центру. Строка «г. Астана ... дата» — **вся строка, включая табуляции, тоже bold** (легко упустить — в эталоне это не просто обычный текст). Заголовки разделов — 12pt bold. В эталоне разделы 1 и 2 идут БЕЗ слова «РАЗДЕЛ» («1. ОБЩАЯ ИНФОРМАЦИЯ», «2. ГРАФИК ОСВОЕНИЯ СРЕДСТВ ПО ПРОЕКТУ»), а разделы 3–5 — СО словом («РАЗДЕЛ 3. ...», «РАЗДЕЛ 4. ...», «РАЗДЕЛ 5. ВЫВОДЫ»). Воспроизводить как есть, не унифицировать.

### 2. ГРАФИК ОСВОЕНИЯ СРЕДСТВ ПО ПРОЕКТУ

Только таблица, БЕЗ пояснительного текста до или после. Строки — по этапам (Средства 1 этапа / 2 этапа / 3 этапа / ... / Итого), колонки: Запланировано (грант, софин.) / Факт (грант, софин.) / Экономия (грант, софин.) / Примечание. Данные — из Excel ФЭД по каждому уже пройденному этапу; если данных по какому-то этапу нет — строка с пометкой «[ЗАПОЛНИТЬ ФЭД]», без попытки восстановить цифры из других документов.

Жирность: строка-заголовок таблицы — **вся жирная**. Строки «Средства N этапа» — название этапа (первая колонка) НЕ жирное, но ВСЕ числовые колонки (план/факт/экономия по гранту и софинансированию) — **жирные**. Строка «Итого» — **жирная целиком** (включая слово «Итого» и все числа).

### РАЗДЕЛ 3. АЦИВС ПО ЦЕЛЕВОМУ ИСПОЛЬЗОВАНИЮ ВЫДЕЛЕННЫХ СРЕДСТВ

Только таблица (12 колонок: №, Наименование статьи, План грант/софин., Факт грант/софин., Экономия грант/софин., Незапланированное грант/софин., Подтверждающие документы, Примечание), БЕЗ текста до/после. 12 статей сметы из Excel ФЭД, с подстроками-расшифровками там, где они есть в источнике (напр. 2.1, 4.1) — не изобретать детализацию, которой нет в Excel (напр. не разбивать статью «Налоговые обязательства» на СО/ОСМС/СН/ОПВР, если в источнике этой разбивки нет).

Жирность: обе строки шапки + строка нумерации колонок (1–12) — **жирные целиком**. В ОСНОВНЫХ строках статей (№1–12, не подстроки) — жирные ТОЛЬКО колонки «№» и «Наименование статьи»; все остальные колонки (числа, документы, примечание) — НЕ жирные. Строки-расшифровки (1.1, 2.1, 4.1 и т.п.) — **полностью не жирные**, включая номер и наименование. Строка «ИТОГО» — жирная колонка «ИТОГО» (название) и все числовые колонки план/факт/экономия (2–9); колонки документов/примечания — не жирные.

### РАЗДЕЛ 4. АЦИВС ПО ВЫПОЛНЕНИЮ МЕРОПРИЯТИЙ КАЛЕНДАРНОГО ПЛАНА

Жирность: строка-заголовок — жирная целиком. В строках данных — жирная ТОЛЬКО колонка «Статус» (значение «Исполнено» и т.п.); остальные колонки — не жирные. (В эталоне встречается точечное выделение отдельных слов/цифр внутри «Достигнутые результаты» — это несистемное авторское выделение конкретных данных того проекта, воспроизводить не нужно.)

### РАЗДЕЛ 5. ВЫВОДЫ

Весь текст раздела — **обычным (не жирным) шрифтом**. Текстовый блок по структуре эталона:

1. Вводный абзац: «Грантополучателем – [ГП] предоставлен [промежуточный/итоговый (заключительный)] отчёт по реализации [N]-го этапа по проекту ИРН [ИРН] «[название]» (далее – Проект), реализуемого в рамках Договора № [номер] от «[дата]».»
2. Абзац о мероприятиях: «По выполненным мероприятиям согласно Календарному плану и оплаченным счетам согласно Смете расходов подтверждающие документы предоставлены в полном объёме, что подтверждает исполнение мероприятий и освоение выделенной суммы по [N]-му этапу.»
3. Абзац с параметрами этапа: срок реализации, сумма гранта, сумма софинансирования этапа.
4. Абзац-подводка: «При проведении анализа целевого использования выделенных средств представленных документов [промежуточного/итогового] отчёта по освоению средств Проекта по Договору № [номер] от «[дата]» выявлено:»
5. Блок «1. По средствам гранта:» с подпунктами 1)–5): сумма фактических выплат; экономия; остаток на эскроу-счёте; остаток собственных средств ГП; сумма к возврату Фонду.
6. Пункт «2. По средствам софинансирования:» — краткая констатация исполнения (сумма, % от плана).
7. Итоговый абзац о сумме к возврату / отсутствии суммы к возврату.
8. Блок «Согласно Приложению 4 Договора «Отчет по анализу эффективности реализации проекта» за отчётный период:» — план/факт по объёму реализуемой продукции, охранным документам (патенты), лицензионным соглашениям — только для итогового отчёта, и только если эти данные явно предоставлены (не додумывать).

**По умолчанию Раздел 5 НЕ включает список «Замечаний» и НЕ включает рекомендацию «принять/вернуть на доработку»** — это решение менеджера. Добавлять их только если пользователь явно попросил включить нарушения/замечания или явно указал рекомендацию. Если пользователь просит убрать замечания — убирать полностью, включая ссылающуюся на них рекомендацию, не заменяя её собственной формулировкой.

### БЛОК ПОДПИСЕЙ

Формат каждой строки: `Должность\t_________________ / ФИО` затем на новой строке `\t(подпись)\t`. Метки «СОГЛАСОВАНО:» и «ОЗНАКОМЛЕНЫ:» — **bold**; сами строки подписантов, «(подпись)» и «М.П.» — НЕ жирные.

```
Менеджер ДКТ №[N]/уполномоченное лицо      _________________ / [ФИО]
                                                              (подпись)
Экономист                                   _________________ / [ФИО]
                                                              (подпись)

СОГЛАСОВАНО:
Директор ДКТ №[N]                           _________________ / [ФИО]
                                                              (подпись)
Управляющий директор                        _________________ / [ФИО]
                                                              (подпись)
Финансовый директор – Главный бухгалтер     _________________ / [ФИО]
                                                              (подпись)

ОЗНАКОМЛЕНЫ:
Руководитель проекта                        _________________ / [ФИО или пусто]
                                                              (подпись)
Руководитель Грантополучателя                _________________ / [ФИО или пусто]
                                                              (подпись)                    М.П.
```

Никогда не подставлять реальные ФИО по умолчанию/по памяти для другого проекта или другого ДКТ без явного запроса пользователя — состав подписантов уточнять для каждого проекта/команды ДКТ отдельно (запомненный состав для конкретной команды ДКТ хранится в памяти проекта и переиспользуется только для неё).

## ШАГ 1: ГЕНЕРАЦИЯ DOCX

Используй `python-docx`:
- Шрифт: Times New Roman, 12pt (основной текст и таблицы); заголовок документа — 14pt bold по центру; заголовки разделов — 12pt bold.
- Отступ первой строки абзаца: 1,0 см.
- Межстрочный интервал: одинарный (1,0) везде.
- **Ориентация: альбомная (landscape)** — не книжная.
- Поля: верх/низ/право — 1,5 см; лево — 3 см.
- Заливка таблиц: строка-заголовок таблицы и строка «ИТОГО» — серая D9D9D9; строки-расшифровки статей (напр. 1.1, 2.1, 4.1) — светло-серая F5F5F5; обычные строки и таблица Раздела 1 — без заливки.
- Жирность (bold) — отдельная от заливки ось форматирования, легко упустить: применять по правилам, описанным в каждом разделе выше (заголовки/шапки таблиц/строка «Итого»/«ИТОГО»/№+наименование основных статей/колонка «Статус»/метки СОГЛАСОВАНО и ОЗНАКОМЛЕНЫ — жирные; весь остальной текст, включая Раздел 5 целиком и строки подписантов, — не жирный).
- Границы таблиц: тонкая одинарная линия (0.5pt / sz=4), сплошная, чёрная, по всем ячейкам.

Имя файла: `[ИРН]_ЗАКЛЮЧЕНИЕ_АЦИВС_[тип]_этап[N].docx`

## Правила

- Все суммы: цифрами и прописью в скобках (там, где это есть в эталоне, напр. Раздел 1).
- Даты: «___» _________ 202_ г. (в титуле) и ДД.ММ.ГГГГ (в таблицах).
- Формат сумм: `XXX XXX XXX,XX тенге`.
- Если данных по разделу нет — оставляй структуру с пометкой «[ЗАПОЛНИТЬ]», не сверяя и не восстанавливая цифры из других документов по своей инициативе.
- Финальное решение (принять/вернуть/замечания/рекомендация) — ВСЕГДА за менеджером, не додумывать.
- Excel-анализ ФЭД — единственный источник финансовых данных; никаких сопоставлений с другими документами без явного запроса.
- При наличии присланного пользователем эталонного .docx — всегда сверяться с ним построчно (paragraph-by-paragraph) и по run.bold на уровне ячеек таблиц, а не полагаться только на этот скилл.
- Контрольные стопы: после Шага 0, после Шага 2.
