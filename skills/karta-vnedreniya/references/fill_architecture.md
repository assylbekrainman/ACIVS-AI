# Архитектура заполнения «Карты внедрения» (Приложение №1)

Документ описывает **логику** заполнения формы: модель данных, источники,
правила вывода каждого поля, режимы, вариативные/вставляемые строки и валидацию.
Основано на 4 реальных заполненных картах (`references/examples/`) и форме,
утв. Правлением АО «Фонд науки» 18.05.2026.

---

## 1. Каркас формы (что фиксировано, что переменно)

Таблица = 8 столбцов:

| # | Столбец | Тип | Кто заполняет |
|---|---------|-----|---------------|
| 0 | № | фикс. (нумерация) | каркас |
| 1 | Наименование мероприятия | фикс., кроме конфиг-строк | каркас / проект |
| 2 | Форма завершения, измеримый результат | фикс., кроме конфиг-строк | каркас / проект |
| 3 | **План** | переменное | проект |
| 4 | **Факт** | переменное | проект (на отчёте) |
| 5 | **Ответственный исполнитель** | переменное | проект |
| 6 | **Сроки исполнения** | переменное | проект |
| 7 | **Примечание** | переменное | проект (опц.) |

**Каркас (фиксированные строки):** 1, 2, 3, 4, 4.1, 4.2, 4.3, 4.3.1, 4.3.2,
4.3.3, 4.4, 4.5, 4.6, 4.6.1, 4.6.2, 4.7, 5, 5.1, 5.2, 5.3, 6, 6.1.
Строки-заголовки разделов (4, 4.3, 4.6, 5, 6) переменные ячейки не заполняют.

**Конфиг-строки** (название и форма завершения — проектные, в каркасе пустые):
`4.3.1, 4.3.2, 4.3.3, 6.1`. Их `name` задаётся по проекту (примеры из реальных
карт: «разработка брендбука» / «Создание сайта, SEO» / «Участие в выставках»).

**Вставляемые строки** (нет в каркасе, добавляются при наличии): подпункты типа
`1.1` (доп. ОИС), `6.2`, `6.3` (доп. мероприятия). Клонируются из соседней
строки с сохранением форматирования.

## 2. Модель данных (вход)

```python
DATA = {
  'gp':       'ТОО «...»',              # Грантополучатель
  'irn':      'DP23692275',             # ИРН (→ имя файла)
  'irn_name': 'DP23692275 «...»',       # ИРН + наименование проекта
  'dogovor':  '№59 от 29.08.2024 года', # Договор
  'mode':     'plan' | 'report',        # стадия: планирование / отчёт
  'rows': {                             # переопределение каркасных строк по №
     '1':   {'plan':'1','fact':'1','otv':'Руководитель проекта','srok':'Декабрь 2025 г.'},
     '4.3.1':{'name':'Создание сайта, SEO','plan':'Исполнить','otv':'Спец. по коммерциализации','srok':'Декабрь 2024 г.'},
     ...
  },
  'extra_rows': [                       # вставляемые строки
     {'after':'1','num':'1.1','name':'Защита ИС (этап 2)','plan':'1','otv':'Руководитель проекта','srok':'Декабрь 2026 г.'},
     {'after':'6.1','num':'6.2','name':'...','plan':'Исполнить', ...},
  ],
}
```

Поля строки: `name` (только конфиг/вставка), `plan`, `fact`, `otv`, `srok`, `prim`.
Любое поле опционально → пустая ячейка.

## 3. Источники данных (откуда берётся значение)

| Поле | Первичный источник | Резерв |
|------|--------------------|--------|
| gp, irn, irn_name | память `snadyn_portfolio.md` по ИРН | заголовок отчёта ГП |
| dogovor | договор гранта / реестр | спросить пользователя |
| plan (кол-ва, суммы) | **Последний КП** (актуальная ред. по Доп.соглашению) + **СЭП** | спросить ГП |
| fact | **отчёт ГП** (аннотац./промеж./итог.) | — |
| otv (роль) | состав проектной группы (память/КД) | типовая роль (см. ниже) |
| srok | Календарный план (помесячно) | год завершения этапа |
| prim | пояснения ГП | — |

**Карта = синтез последнего Календарного плана и СЭП.** Перед заполнением обязательно
убедись, что КП последний — он может быть изменён по Доп.соглашению. Плановые
показатели не выдумываются, а переносятся. Нет данных → заполнить каркас + роли,
План/Сроки пометить как требующие данных от ГП.

### Правило «только 2026 год»

Карта внедрения заполняется **исключительно по мероприятиям текущего 2026 года**.
Мероприятия прошлых лет в текущую карту не включаются. Если мероприятие в КП
относится к 2025 году или ранее — пропускаем (или ставим «Не запланировано»
в Plan, если строка обязательная).

### Как читать СЭП по годам проекта

Данные из СЭП берутся за столбец, соответствующий 2026 году для данного проекта:

| Год старта проекта | Столбец СЭП для 2026 г. |
|--------------------|-------------------------|
| 2023 (4-летний)    | «3 год» и/или «4 год»   |
| 2024               | «2 год» и/или «3 год»   |
| 2025               | «1 год» или «2 год»     |

**Важно:** По проектам 2024–2025 в СЭП «пункт 7» (продажи) могут стоять нули —
это нормально, если старт продаж ещё не наступил. Нули переносятся как есть
(0 тенге или «-»). Не домысливай показатели — пиши то, что в СЭП.

### Сопоставление полей Карты и пунктов СЭП

| Строка Карты | Соответствующий пункт СЭП |
|--------------|---------------------------|
| 4.6.1 Внутренний рынок (тенге) | СЭП п.7 — объём реализации на внутреннем рынке |
| 4.6.2 Экспорт с указанием страны (тенге) | СЭП п.7 — объём реализации на экспорт |
| 5.2 Налоги (тенге) | СЭП п.8 — налоговые поступления |
| 5.3 Авторское вознаграждение (роялти) `***` | **Только при наличии** — **НЕ** берётся из п.12 СЭП! |

**О символе `***`:** В форме Карты `***` означает «заполняется при наличии». Если
мероприятие/показатель не предусмотрено проектом — ставь «Не запланировано» или
«-». Это касается строк: 1 (Защита ИС), 2 (Сертификация), 4.2, 4.5, 4.6.2, 5.3
и раздела 6.

**О строке 5.3 (Роялти) — особо важно:** Роялти — это авторское вознаграждение
по договору с правообладателем ИС (лицензионный договор). Источник — отдельный
договор, а не СЭП. **Ни в коем случае не берётся из п.12 СЭП** (п.12 СЭП описывает
иное — не путать). Если такого договора нет → «Не запланировано» / «-».

## 4. Правила вывода полей (трансформации)

1. **Режим `plan`** → столбец «Факт» **пустой** (КД: «заполняются все графы,
   кроме графы Факт»). Режим `report` → «Факт» заполняется из отчёта.
2. Показатель не предусмотрен проектом → `plan = "-"` или `"Не запланировано"`,
   `otv = "-"`, `srok = "-"` (см. реальные карты: ст. 2, 4.2, 4.6.2, 5.3).
3. Качественные мероприятия (3, 4.3.x, 6.x) → `plan = "Исполнить"`,
   на отчёте `fact = "Исполнено"`.
4. Количественные (1, 4.1, 4.2, 4.7, 5.1) → число; допускается «12», «3 вида ресурсов».
5. Денежные (4.5, 4.6.1, 4.6.2, 5.2, 5.3) → сумма в тенге, пробелы разрядов;
   допускается суффикс « тенге» и копейки через запятую («24 722 552,07 тенге»).
6. Конечный потребитель (4.4) → «Не менее N договора(ов)» (напр., «Не менее 1
   договора» или «Не менее 2 договоров») — конкретное число из КП или типовое.
7. **Сроки** — единый формат проекта: «Месяц ГГГГ г.» (часто «Декабрь 2026 г.» —
   конец этапа). Один год завершения для большинства строк.
8. **Ответственный** — роль, не ФИО. Допускается уточнение («Руководитель
   проекта, ведущий научный сотрудник») и составной субъект
   («Грантополучатель/Частный партнёр», «Проектная группа»).
9. **Маппинг столбцов Карты → столбцов КП (КРИТИЧНОЕ ПРАВИЛО):**

   | Столбец Карты | Берётся из столбца КП |
   |---|---|
   | **Форма завершения, измеримый результат (col 2)** | «**Ожидаемый результат**» КП — документы-подтверждения (договора, акты, отчёты, патенты и т.д.) |
   | **План (col 3)** | «**Наименование мероприятия**» КП — действие в форме глагола («Реализация продукции», «Достижение объема…») |

   Правило действует для строк с переопределяемой Формой завершения: **4.1, 4.2, 4.4,
   4.3.1–4.3.3, 6.1 и вставляемые строки**. Для фиксированных строк (4.5, 4.6.x, 5.x
   и т.д.) Форма завершения берётся из каркаса, в столбец «План» идёт число/сумма.

   **Частая ошибка:** записать Наименование мероприятия в col 2 (Форма завершения),
   а Ожидаемый результат — в col 3 (План). Это неверно. Мнемоника:
   - **col 2** = *что получим* (документ, артефакт — из «Ожидаемый результат» КП);
   - **col 3** = *что делаем* (действие в форме глагола — из «Наименование мероприятия» КП).

   Не придумывай тексты — переноси дословно из соответствующего столбца КП.

### Типовые роли по строкам (default, если не задано)

| Строки | Роль по умолчанию |
|--------|-------------------|
| 1, 1.x, 4.7, 5.1, 5.3, 6.x | Руководитель проекта |
| 3 | Технолог / Менеджер по производству |
| 4.1, 4.2, 4.3.x, 4.4, 4.6.1, 4.6.2 | Специалист по коммерциализации |
| 4.5 | **Грантополучатель/Частный партнёр** |
| 5.2 | Бухгалтер проекта |
| 2 | Руководитель проекта (или «-», если не запланировано) |

## 5. Алгоритм заполнения (последовательность)

```
1. Найти последний актуальный КП (проверить наличие Доп.соглашений — брать
   самую свежую редакцию).
2. Загрузить чистый каркас template_karta.docx.
3. Заполнить шапку: {{GP}}, {{IRN_NAME}}, {{DOGOVOR}}.
4. Построить карту № → индекс строки (пропустить 2 строки шапки таблицы).
5. ВСТАВИТЬ extra_rows:
     для каждой — клонировать строку 'after', вставить следом,
     записать num + name, очистить переменные ячейки.
   Перестроить карту № → индекс.
6. Для каждой строки DATA['rows']:
     - Если мероприятие в КП 2026 года есть → заполнить plan/otv/srok;
     - Если мероприятие *** и в КП 2026 года НЕТ → plan="Не запланировано",
       otv="-", srok="-";
     - Для финансовых строк (4.6.1, 4.6.2, 5.2) → брать из СЭП нужного года
       (см. таблицу "Как читать СЭП");
     - Если задан name (конфиг-строка) → записать в col1;
     - fact записывать ТОЛЬКО при mode == 'report'.
7. Сохранить Карта_внедрения_<ИРН>.docx.
8. Проверить (конвертация в PDF/картинку), отдать пользователю.
```

## 6. Валидация (перед выдачей)

- Шапка: ГП, ИРН и наименование, № и дата договора — не пустые.
- Нет «висящих» плейсхолдеров `{{...}}`.
- В режиме `plan` столбец «Факт» пуст по всем строкам.
- У каждой содержательной строки заполнены План, Ответственный, Сроки
  (или явное «-» / «Не запланировано»).
- Суммы — числовой формат; сроки — «Месяц ГГГГ г.».
- Конфиг/вставленные строки имеют название.
- Строки 4.6.1/4.6.2 → сверены с СЭП п.7; строка 5.2 → с СЭП п.8.
- Строка 5.3 → НЕ взята из п.12 СЭП; заполнена только при наличии договора.
- Строка 4.5 (Ответственный) → «Грантополучатель/Частный партнёр».
- Все показатели → только по 2026 году (из актуального КП и СЭП).
