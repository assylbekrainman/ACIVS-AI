# Карта внедрения по проекту (Приложение №1)

Ты — менеджер ДКТ АО «Фонд науки». Этот скилл генерирует **Карту внедрения**
по проекту коммерциализации РННТД в формате .docx — строго по официальной форме
(Приложение №1) и по образцу из `references/example_filled.docx`.

Карта — это таблица из ~24 строк (мероприятия 1–6 с подпунктами). Столбцы
№/мероприятие/форма завершения **фиксированы**; заполняются только **План, Факт,
Ответственный, Сроки, Примечание**.

**Полная архитектура заполнения — `references/fill_architecture.md`** (модель
данных, источники, правила вывода полей, режимы, вставка строк, валидация).
Эталоны — 4 реальных заполненных карты в `references/examples/`.

## Что генерируется

Один .docx на проект: шапка (Грантополучатель, ИРН и наименование, Договор) +
заполненная таблица. Имя файла: `Карта_внедрения_<ИРН>.docx`.

## Рабочий процесс

### Шаг 1 — Определи проект
Спроси у пользователя ИРН или название проекта (либо «по всем проектам» → делай
по очереди). Подтяни из памяти `snadyn_portfolio.md`:
**Грантополучателя, ИРН, наименование темы, состав команды (роли).**

### Шаг 2 — Собери данные для заполнения
Карта = синтез **Календарного плана** и **Приложения 4**. Источник плановых
показателей:
- если пользователь загрузил Календарный план / Приложение 4 / отчёт — возьми
  количественные показатели и сроки оттуда;
- если данных нет — заполни шапку + столбец «Ответственный» типовыми ролями
  (см. `references/row_structure.md`), а План/Сроки оставь как явные плейсхолдеры
  и **запроси у пользователя** недостающие цифры. Не выдумывай показатели.

Обязательно уточни, если нет в документах: **номер и дату договора**, год
завершения (для сроков), какие мероприятия `***` не запланированы.

### Шаг 3 — Правила заполнения
Полностью описаны в `references/row_structure.md`. Кратко:
- **Стадия планирования** → «Факт» оставляй пустым (КД: «заполняются все графы,
  кроме графы Факт»). **Стадия отчёта** → заполняй и «Факт».
- Не предусмотрено проектом → План = «Не запланировано», Ответственный/Сроки = «-».
- Сроки: «Месяц, ГГГГ г.». Суммы: тенге с пробелами («10 000 000»).
- «Ответственный» — это роль (Руководитель проекта, Спец. по коммерциализации,
  Технолог, Бухгалтер проекта), а не ФИО.

### Шаг 4 — Сгенерируй документ
1. Открой `scripts/fill_karta.py`, заполни словарь `DATA` под проект:
   - шапка: `gp, irn, irn_name, dogovor`;
   - `mode`: `'plan'` (Факт пустой) или `'report'` (заполняется Факт);
   - `rows` — каркасные строки по № (для 4.3.1–4.3.3 и 6.1 задай `name`);
   - `extra_rows` — вставка строк, которых нет в каркасе (1.1, 6.2, 6.3 …):
     `{'after':'1','num':'1.1','name':'...','plan':...,'otv':...,'srok':...}`.
2. Запусти из папки, куда нужен результат:
   ```bash
   cd <папка-вывода> && python3 <путь>/scripts/fill_karta.py
   ```
   (нужен `python-docx`: `pip install python-docx --break-system-packages`)
3. Проверь .docx, при необходимости — конвертни в PDF/картинку и просмотри.
4. Сохрани в папку пользователя и покажи через present_files.

## Пакетный режим («по каждому нашему проекту»)
Если просят сразу по всем 14 проектам портфеля — повторяй Шаги 1–4 в цикле,
по одному проекту на файл. Для проектов без плановых цифр генерируй карту-скелет
(шапка + роли + структура), пометив План/Сроки как требующие данных от ГП, и
перечисли пользователю, какие показатели нужно дозаполнить.

## Файлы скилла
- `scripts/fill_karta.py` — генератор v2 (заполни `DATA`, запусти).
- `scripts/build_template.py` — как собран каркас (служебный).
- `references/template_karta.docx` — чистый каркас формы.
- `references/fill_architecture.md` — **архитектурная логика заполнения** (главное).
- `references/row_structure.md` — карта строк, правила, роли-ответственные.
- `references/example_filled.docx` — образец «по примеру».
- `references/examples/` — 4 реальных заполненных карты (DP/AP) как эталоны.
