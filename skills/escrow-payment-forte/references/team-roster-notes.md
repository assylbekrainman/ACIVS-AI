# Реестр проектных команд (references/team_roster.csv) — источник и границы

## Откуда

Загружен пользователем 24.08.2026 — файл «команда проектов 2022, 2023, 2024,
2025 (1).xlsx», 4 листа по годам. Из него извлечены только ФИО членов
проектной группы + код проекта (ИРН/DP) + роль + год + статус
(«исходный»/«замена» — если человека в проекте кто-то заменил).

**ИИН (нацID) намеренно не перенесён** — по решению пользователя от
24.08.2026: для сверки по имени в тексте договора ИИН не нужен, а хранить
нацID тысяч людей внутри файла скилла (который может экспортироваться/
загружаться повторно) — лишний риск. Если понадобится более точная сверка
(два тёзки, разные люди) — точный ИИН есть только в исходном xlsx у
пользователя, скрипт сам его не восстановит.

## Что в файле

- 1798 строк, 285 уникальных кодов проектов (ИРН/AP-.../DP-...), годы
  2022–2025.
- Для 2025 года дополнительно есть колонка «грантополучатель» (юрлицо) —
  для 2022-2024 её не было в исходнике, поле пустое.
- «замена» — если по проекту была официальная замена члена группы, в
  реестре есть ОБА имени (кто заменил и кого) под одним ИРН — это сделано
  специально: аффилированность нужно проверять по всем, кто когда-либо
  официально числился в проекте, не только по действующему составу.

## Как это используется в скилле

Шаг 4 SKILL.md («Проверь получателя платежа на аффилированность с ГП»)
теперь включает не только открытые реестры (adata.kz, kompra.kz, egov.kz),
но и этот внутренний список — через `scripts/check_affiliation.py`. Логика:
если учредитель/руководитель/подписант поставщика по имени совпадает с
членом ПРОЕКТНОЙ ГРУППЫ (не обязательно этого же проекта — человек мог быть
в проектной группе одного гранта и одновременно учредителем поставщика
другого), это повод для ручной проверки, а не автоматический отказ.

## Ограничения — не додумывай сверх этого

- Совпадение по ФИО — не доказательство. Однофамильцы в Казахстане
  встречаются часто. Скрипт помечает это явно и просит второе подтверждение
  (обычно — совпадение по адату/kompra.kz + названию юрлица поставщика).
- Файл разовый, актуален на момент загрузки (24.08.2026). Новые проекты
  2026 года и позже сюда не попадут, пока пользователь не пришлёт
  обновлённую выгрузку — не делай вид, что реестр покрывает текущий год.
- Реестр — это ПРОЕКТНАЯ ГРУППА (кто работает по гранту), не реестр
  учредителей юрлиц. Он не заменяет проверку по adata.kz/kompra.kz, кто
  реально является учредителем/директором поставщика — это по-прежнему
  отдельный обязательный пункт Шага 4.
