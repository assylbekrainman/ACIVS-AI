# Проверка контрагента через API КГД МФ РК

Ты — менеджер ДКТ АО «Фонд науки». Этот скилл делает запрос к официальному
сервису Комитета государственных доходов МФ РК «Api сведения по контрагентам
(Открытые данные)» и возвращает статус ИП/ЮЛ по ИИН/БИН: резидентство,
режим налогообложения, задолженность по налогам, признаки банкротства,
недействующего/недействительного статуса и др.

Источник спецификации API: `references/api_reference.md`
(инструкция от Администратора КГД + страница
https://portal.kgd.gov.kz/ru/pages/info-services/find-information-for-ip-ul).

## Когда использовать

- Проверка Флага 1 «Аффилированность поставщика» в `acivs-red-flags` —
  но для аффилированности БИН достаточно просто сравнить (см. тот скилл);
  этот скилл нужен, когда важен **статус контрагента**: банкрот ли,
  действующий ли, есть ли налоговая задолженность, стоит ли на учёте по НДС.
- Проверка поставщика перед приёмкой документов по статьям сметы (`acivs-docs-check`).
- Быстрая справка «что известно о контрагенте по БИН/ИИН» вне контекста
  конкретной проверки отчёта.

## Предварительные условия

Нужен токен `X-Portal-Token`, который выдаёт Администратор портала КГД МФ РК
по официальному запросу от АО «Фонд науки». Без токена запросы вернут `401`.

Задай переменные окружения (один раз на сессию/машину):

```bash
export KGD_PORTAL_HOST="https://portal.kgd.gov.kz"   # можно не задавать — это значение по умолчанию
export KGD_PORTAL_TOKEN="<токен, выданный Администратором КГД>"
```

Либо создай файл `.env` рядом со скриптом на основе `scripts/.env.example`
(в `.env` не коммитится в git — файл содержит секрет).

## Как использовать

Скрипт `scripts/kgd_client.py` — самостоятельный CLI, зависимостей кроме
стандартной библиотеки и `requests` не требует.

Одна проверка по ИИН/БИН:

```bash
python3 skills/kgd-counterparty-check/scripts/kgd_client.py 071140005693
```

Несколько БИН сразу (например, все поставщики по отчёту):

```bash
python3 skills/kgd-counterparty-check/scripts/kgd_client.py 071140005693 990140001234 --json
```

Флаги:
- `--json` — вывести сырой JSON-ответ API вместо читаемой сводки (удобно
  для передачи дальше в заключение АЦИВС или в другой скрипт).
- `--host` / `--token` — переопределить переменные окружения разово.

## Что делать с результатом

Скрипт сам подсвечивает потенциальные красные флаги на основе полей ответа:

| Поле ответа | Когда считается флагом |
|---|---|
| `bankrupt.ru` | ≠ «Нет данных» → контрагент в реестре банкротов |
| `inactive.ru` | ≠ «Нет данных» → налогоплательщик признан бездействующим |
| `registrationInvalid.ru` / `reRegistrationInvalid.ru` | ≠ «Нет данных» → регистрация признана недействительной |
| `operationsWOWork.ru` | ≠ «Нет данных» → сделки без факта выполнения работ (п. 3 ст. 265 НК РК) |
| `esfRestrinctions.ru` | ≠ «Нет данных» → ограничения по выписке ЭСФ |
| `regAddressAbsent.ru` | = «Да» → отсутствует по юридическому адресу |
| `courtDecisionRegistry.ru` | ≠ «Нет данных» → есть решение суда в реестре |
| `taxDebt` | > 0 → есть налоговая задолженность (сумма в тенге) |

Если хотя бы один флаг сработал — перенеси его в отчёт о красных флагах
(`acivs-red-flags`) с пометкой источника «API КГД, дата актуальности:
`actuality`».

Если у ответа `regAddressAbsent`, `bankrupt` и т.п. равны «Нет данных» —
это означает отсутствие записи в соответствующем реестре, а НЕ подтверждение
благонадёжности; так и формулируй в выводах ("данных о банкротстве нет" ≠
"контрагент не банкрот").

## Коды ошибок API

| Код | Значение | Действие |
|---|---|---|
| 200 | Успешно | — |
| 400 | Синтаксическая ошибка запроса | Проверь формат ИИН/БИН (12 цифр) |
| 401 | Не авторизован | Проверь `KGD_PORTAL_TOKEN` |
| 404 | Доступ к сервису запрещён | Обратись к Администратору КГД — токен не активирован или не имеет доступа к сервису |
| 500 | Ошибка на сервере | Повтори запрос позже, это не ошибка на нашей стороне |

## Postman (альтернативный способ)

Если нужно проверить контрагента вручную без Python — используй готовую
коллекцию и окружение Postman, которые были собраны по этой же спецификации
(файлы `KGD_Svedeniya_po_kontragentam.postman_collection.json` и
`KGD_Portal.postman_environment.json`, переданы пользователю отдельно).
Логика идентична: тот же эндпоинт, заголовок и тело запроса.
