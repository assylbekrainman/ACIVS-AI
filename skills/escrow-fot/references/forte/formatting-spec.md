# Типографика и структура — эталон АО «Forte Bank»

Извлечено из XML реального письма
(`assets/forte/example-real-forte-salary-only-jan-jul2026.docx`, проект DP25993931,
ТОО «Научно-технологический центр воды», Петропавловский филиал, период
январь–июль 2026). Одноязычное письмо (только русский текст).

**Важная особенность этого эталона: он покрывает ТОЛЬКО зарплату (Заработная
плата к выплате: 6 771 618 тенге), других 7 категорий (ОПВ/ИПН/Соцналог/
Соцотчисления/ОСМС×2/ОПВР) в письме НЕТ.** Причина подтверждена
пользователем: этот конкретный ГП оплатил налоги/взносы за свой счёт, а не
из средств гранта — это не ограничение формата Forte. Если в письме-
обосновании ГП присутствует любая из 7 категорий — оформляй её блоком по
аналогии со структурой зарплатного раздела ниже (структура самих 7 блоков
для Forte пока не подтверждена реальным примером — см.
`known-gaps-checklist.md`).

## Шрифт и кегли

- Шрифт — **Times New Roman** (задан через `docDefaults` в styles.xml, не
  переопределяется на уровне отдельных ранов).
- **Основной текст письма** (вступительные абзацы, строки «Заработная плата
  к выплате:», «Транзитный счёт...», «БИК:», «КНП») — явно `w:sz="28"` =
  **14pt**. Крупнее, чем у БЦК/Alatau (11-12pt).
- **Таблицы сотрудников и заключительный блок** (реквизиты Фонда науки,
  подписи) — размер НЕ задан явно ни на одном уровне (нет ни на ранах, ни в
  `docDefaults`, ни в стилях) → используется жёсткий дефолт Word **10pt**
  (`w:sz="20"`, стандартное фолбэк-значение при полном отсутствии указания
  размера).
- Заголовок «Эскроу-расписка» — 14pt (тот же размер, что у остального
  основного текста), жирный, по центру — тот же паттерн, что у остальных
  банков (не увеличен отдельно).

## Жирность — менее последовательная, чем у БЦК/Alatau

В этом письме жирность местами выглядит как артефакт copy-paste, а не
системное форматирование (например, отдельные буквы внутри номера счёта или
названия банка оказываются жирными без видимой логики — «K», «Z», «F» в
середине номера эскроу-счёта). Общий узор всё же прослеживается:
- **Жирные:** заголовок «Эскроу-расписка», название филиала банка в шапке
  («Петропавловский филиал», «Forte Bank»), сумма прописью/цифрами в абзаце
  «Просим Вас осуществить оплату...», вся строка «Заработная плата к
  выплате: ... тенге», строки «Транзитный счёт АО «...»: ...»/«БИК:»/«КНП»
  целиком, шапка таблицы (ФИО/ИИН/Банк/Расчётный счёт/Сумма), строка «Итого»
  с суммой, название ГП и ФИО подписанта в блоке «Получатель:», «Банк:» и
  название филиала.
- **Не жирные:** вступительный абзац со ссылкой на договор (кроме номера
  эскроу-счёта, который жирный — похоже на непреднамеренное форматирование),
  данные сотрудников в таблице (ФИО/ИИН/банк/счёт — все НЕ жирные, жирная
  только итоговая строка), реквизиты Фонда науки (кроме названия «АО «Фонд
  науки»» и должности/ФИО подписанта).
- Не пытайся воспроизвести побуквенную жирность номеров счетов — это
  случайность форматирования исходного файла, не паттерн.

## Выравнивание

- Заголовок «Эскроу-расписка» — по центру.
- Большинство абзацев основного текста и строк реквизитов — по ширине
  (`w:jc="both"`), в отличие от Alatau, где поля реквизитов были по левому
  краю без явного выравнивания.
- Заголовки таблицы и часть ячеек данных — по ширине или по центру (смешано,
  не полностью единообразно) — используй по центру как безопасный дефолт для
  новой генерации.
- Строка «Итого» — метка по правому краю (`w:jc="right"`), сумма — по центру.

## Таблицы

- Одна отдельная таблица **на каждую транзитную группу** (не одна общая
  таблица на всех сотрудников): в этом примере 2 таблицы — одна для группы
  «АО «Банк ЦентрКредит»» (3 сотрудника), другая для группы «АО «Kaspi
  Bank»» (1 сотрудник). Перед каждой таблицей — 3 строки текста: «Транзитный
  счёт АО «...»: <ИИК>», «БИК: <БИК>», «КНП <332>».
- Колонки таблицы: **ФИО | ИИН | Банк | Расчётный счёт | Сумма, тенге** — те
  же 5 колонок, что и в зарплатной таблице Alatau. Колонка «Расчётный счёт»
  показывает ЛИЧНЫЙ счёт сотрудника (для справки/сверки), а не транзитный —
  реальным получателем всей суммы группы является транзитный счёт, указанный
  текстом НАД таблицей. Это тот же принцип, что описан в
  `references/shared/transit-accounts.md`.
- В конце каждой таблицы — строка «Итого» с суммой по группе (жирным).
- Границы таблиц не заданы явно в document.xml (нет `w:tcBorders` в первой
  найденной таблице) — визуально сетка, скорее всего, идёт через
  унаследованный стиль таблицы; при генерации используй тонкие сплошные
  линии (как у остальных банков) как безопасный дефолт.

## Структура письма построчно

1. Шапка (двухстрочная, разделена табуляцией на левую/правую части):
   - строка 1: «Исх. № ___» слева, «Петропавловский филиал» справа (жирным);
   - строка 2: «от «__» _____ 2026 г.» слева, «АО "Forte Bank"» справа
     (жирным).
   Название конкретного филиала банка (не только «Forte Bank» в целом) —
   обязательная часть шапки, бери из Договора эскроу-счёта ГП.
2. Заголовок по центру: «Эскроу-расписка».
3. Абзац со ссылкой на Договор на открытие эскроу-счёта: номер договора,
   номер и сам номер эскроу-счёта (IBAN) в скобках, дата, стороны (Банк,
   Получатель-ГП, АО «Фонд науки» — Клиент).
4. Абзац с привязкой к смете расходов: за какой период выплата, статья сметы,
   номер и дата Договора гранта, номер и название проекта.
5. Абзац «Просим Вас осуществить оплату в размере ... тенге по следующим
   реквизитам:» — сумма прописью и цифрами.
6. Строка «Заработная плата к выплате: <сумма> тенге» — жирным.
7. Далее — блоки по числу транзитных банков сотрудников (в этом примере 2):
   строки «Транзитный счёт АО «...»: ИИК» / «БИК: ...» / «КНП 332», затем
   таблица сотрудников этой группы с итогом.
   **В этом эталоне нет ни одной из 7 налоговых/взносовых категорий** — если
   пользователь просит полную расписку (ФОТ + налоги), уточни, нужно ли
   отдельное письмо на каждую категорию или общий формат для Forte таков же,
   как у БЦК/Alatau (см. known-gaps-checklist.md).
8. Блок «АО «Фонд науки»» (Клиент/Плательщик): название жирным, адрес, БИН,
   ИИК, БИК, банк, Кбе — обычным шрифтом.
9. Подпись Фонда науки: должность «Управляющий директор» (жирным) + строка
   «ФИО подписанта ______________» (жирным) + «(подпись)» (обычным).
10. **Блок подписи Получателя (ГП)** — «Получатель:» (жирным) + название ГП
    + место для подписи + ФИО уполномоченного лица ГП (жирным) + «М.П.»/
    «(подпись уполномоченного лица)» (обычным).
11. **Блок подписи Банка** — «Банк:» (жирным) + полное название банка и
    филиала (жирным) + место для подписи + «М.П.»/«(ФИО, подпись
    уполномоченного лица)» (обычным).

## Валюта

Письмо (2026 г.) пишет «тенге» без ң везде — но, как и в случае Alatau,
не копируй это буквально: по умолчанию для новых расписок Фонда используй
«теңге» с ң, если пользователь явно не укажет иное для этого конкретного
банка/ГП.

## Ключевое структурное отличие от БЦК/Freedom/Alatau

**У Forte письмо подписывается ТРЕМЯ сторонами прямо на самом документе**
(Фонд науки/Клиент, Получатель/ГП, Банк/филиал) — в отличие от БЦК/Freedom/
Alatau, где расписку подписывает только Фонд науки, а банк и ГП участвуют
через отдельный внутренний блок «Принято в работу...» (Менеджер/Начальник)
или вообще не расписываются на самом письме. В этом эталоне блока «Принято в
работу» НЕТ вообще — вместо него прямые подписи Получателя и Банка. Не
путай эти два разных формата контроля и не добавляй блок «Принято в работу»
в расписки по Forte, если пользователь явно не попросит.
