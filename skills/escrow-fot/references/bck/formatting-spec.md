# Точная типографика эталонного бланка

Источник: реальная заполненная расписка `assets/bck/example-filled-bck-january.docx`
(январь 2026, ТОО «ABasqar», банк БЦК), полученная от пользователя как эталон
оформления. Все значения ниже извлечены напрямую из XML документа
(word/document.xml, word/styles.xml), а не угаданы по картинке — рендер в
LibreOffice может подменять шрифт, если Calibri не установлена в системе
конвертации, и тогда визуально текст выглядит как с засечками (Times/Liberation
Serif), хотя в файле явно прописан Calibri. Ориентируйся на XML-значения, а не
на то, как выглядит рендер.

## Написание валюты — везде «теңге», включая русский текст

По прямому указанию пользователя: слово «тенге» пишется как **«теңге»** (с ң)
во ВСЕХ местах документа, включая русскоязычную колонку/текст — не только в
казахской части. Это правило сильнее обычной практики «на русской стороне —
русское слово «тенге», на казахской — «теңге»»: даже в русских фразах вида
«Сумма: ... теңге 00 тиын» нужно писать «теңге», а не «тенге». Сам эталонный
образец непоследователен в этом (местами «тенге», местами «теңге», в обеих
языковых колонках вперемешку) — не копируй эту непоследовательность, всегда
приводи к «теңге».

## Шрифт и кегль

- Шрифт — тема документа (minorFont) = **Calibri**, отдельно переопределять
  `w:rFonts` не нужно, кроме случаев когда явно требуется другой шрифт.
- Кегль основного текста и всех подписей/меток блоков — **22 half-points = 11pt**
  (`w:sz w:val="22"`). Это касается ВСЕГО текста вне таблиц: вступительного
  абзаца, заголовков блоков «№N Бенефициар», строк БСН/ЖСК/БСК/БеК, подписей.
- Кегль текста ВНУТРИ таблиц (шапка и строки) — **20 half-points = 10pt**
  (`w:sz w:val="20"`), то есть на 1pt меньше основного текста.
- Заголовок «Қолхат» / «Расписка» — тот же кегль 22 (11pt), НЕ увеличенный.
  Разница с обычным текстом — только жирность и центрирование, не размер.

## Что жирное, что нет

Жирным (`<w:b/>`) оформлены:
- Верхний блок «Эскроу-шот шартына / қосымша» — «Приложение / к Договору
  эскроу-счёта».
- Заголовок «Қолхат» / «Расписка».
- Заголовок блока «№N Бенефициар» / «Бенефициар №N» — **жирный И подчёркнутый**
  (`<w:u w:val="single"/>`), не просто жирный.
- Метка «Аты-жөні / Атауы:» / «Наименования:» — жирная, ЗНАЧЕНИЕ (само название
  банка/организации) после неё — тоже жирное.
- Метка «Төлемнің мақсаты:» / «Назначение платежа:» — жирная, но текст цели
  платежа ПОСЛЕ метки — обычный, не жирный.
- Строка «Сомасы: ... тенге 00 тиын» / «Сумма: ... тенге 00 тиын» — **целиком
  жирная**, включая цифры и метку.
- В шапке таблицы сотрудников — жирный текст, отцентрированный.
- Строка «Итого:» в таблице — жирная (минимум ячейка с суммой, обычно вся
  строка).
- Суммы прописью в вводном абзаце (например «Бір миллион сегіз жүз алпыс мың
  төрт жүз сексен») — жирные, весь остальной текст абзаца обычный.

НЕ жирным (обычный вес) оформлены:
- Строки БСН/БИН, ЖСК/ИИК, АО «Банк», БСК/БИК, БеК/Кбе — включая и метку, и
  значение. Это отличается от заголовка блока и метки «Атауы» — только эти
  четыре-пять строк реквизитов набраны обычным весом.
- Данные внутри таблицы (не шапка, не «Итого») — обычный вес.

## Выравнивание

- Вступительные абзацы («Қолхатқа және келесі құжаттарға:» / «В соответствии
  с Распиской и следующими документами:», и далее) — **выравнивание по ширине**
  (`w:jc="both"`, justify), а не по левому краю.
- Заголовок «Қолхат» / «Расписка» — по центру.
- Заголовки блоков «№N Бенефициар» — по левому краю (не по центру).
- Шапка таблицы сотрудников — по центру. Данные таблицы — по левому краю
  (текстовые колонки) и, как правило, по правому краю для колонки «Сумма».
- «Қолдар» (заголовок блока подписей) — по центру.

## Границы таблиц

- Одинарная линия, **`w:sz="4"`** (0.5pt) по всем сторонам ячеек и внутренним
  границам — это стандартная тонкая граница Word, не двойная и не жирная.
- **Заливки/шейдинга у шапки таблицы НЕТ** (`w:shd fill="auto"`, то есть без
  цвета). Не закрашивай шапку серым — это отсебятина, в эталоне шапка белая,
  выделяется только жирным текстом.

## Порядок полей — ОТЛИЧАЕТСЯ по типу бенефициара

Это самое важное структурное наблюдение, которое раньше не учитывалось: набор
и порядок строк реквизитов не одинаков для всех блоков, а зависит от типа
получателя.

### Тип «Зарплата / транзитный счёт» (Kaspi, Народный Банк, любой банк-получатель ЗП)

Порядок строк: **БСН/БИН → БСК/БИК → АО «Банк» → ЖСК/ИИК**. Поля «БеК/Кбе»
**нет вообще** — не «не применимо», а строка физически отсутствует в блоке.

Значение поля «Аты-жөні / Атауы:» — не собственное название банка, а
обобщённая формулировка **«Банк бенефициара по заработной плате на казахском
языке»** / **«Банк бенефициара по заработной плате на русском языке»** (текст
неизменный, язык — просто отражает колонку). Само название банка появляется
только в строке «АО «Банк»» ниже. Это наблюдаемая конвенция эталона — используй
её, если пользователь явно не попросит указывать название банка в поле
«Атауы» напрямую.

### Тип «Институциональный получатель» (Госкорпорация, Комитет казначейства/УГД)

Порядок строк: **БСН/БИН → ЖСК/ИИК → [АО «Банк» — только если получатель
средств физически отличается от держателя счёта] → БСК/БИК → БеК/Кбе**.

- Если счёт принадлежит самой организации-бенефициару (например, Госкорпорация
  «Правительство для граждан» получает свои же взносы) — строка «АО «Банк»»
  **пропускается целиком**, эталон её не пишет и не подставляет
  самореферентное название. (Это уточняет более раннее решение в этом скилле —
  раньше мы писали название организации ещё раз в поле «Банк», в эталоне эта
  строка просто отсутствует.)
- Если реквизиты банка отличаются от названия получателя (например, получатель
  «УГД по [району]», а счёт физически в «ГУ «Комитет казначейства МФ РК»») —
  строка «АО «Банк»» есть и указывает именно держателя счёта, без слова «АО»
  перед государственным учреждением (пишется как есть: «ГУ «Комитет
  казначейства Министерства финансов РК»», без «АО «...»»).
- «БеК/Кбе» **есть всегда** для этого типа (обычно значение 11).

## Вступительный абзац — короче, чем делали раньше

Эталон не расписывает в теле письма номер договора эскроу-счёта, название
банка отдельной фразой и т.п. — только исходящий номер и дата письма-основания:
«1) шығыс № .../... хатпен ДД.ММ.ГГГГж.;» / «1) письмо исх.№.../... от
ДД.ММ.ГГГГг.;», затем сразу «...сәйкес Банктен Шартқа және ҚР заңнамасына
сәйкес Бенефициарға жалпы сомасы ... сұраймыз:». Не добавляй лишних деталей
(номер договора эскроу, ИРН проекта и т.п.) в тело письма сверх того, что есть
в эталоне — если это важно для внутреннего контроля, вынеси отдельным
комментарием в чат, а не в сам документ.

## Блок подписей

Заголовок раздела — **«Қолдар»** (без «/ Подписи» на русском — блок и так
двуязычный по колонкам, отдельного русского слова в заголовке нет).
Далее двумя колонками: «Алушы / Получатель» слева, «Төлеуші / Плательщик»
справа — оба жирные. Ниже: название организации (жирное), БСН/БИН (обычный
вес), должность подписанта (жирная), ФИО с местом для подписи, строка «Қолы /
Подпись:» с прочерком, строка «МО/МП (болған кезде / при наличии):» —
**одна объединённая двуязычная строка**, не отдельно на казахском и отдельно
на русском.

## Внутренняя сверка сумм и примечания — НЕ часть официального документа

Эталонный бланк не содержит ни таблицы «Контрольная сверка суммы», ни раздела
«Примечания» — это была добавка этого скилла для внутреннего контроля. Такую
сверку по-прежнему нужно делать (см. `scripts/check_and_group.py`), но
**показывай её пользователю в чате или отдельным файлом, не вставляй в сам
docx** — эталонный документ должен быть чистым и соответствовать тому, что
реально уходит в банк.

## Найденные в эталоне ошибки — НЕ копировать

Пользователь явно указал на ошибки в этом реальном образце — он эталон по
оформлению, но не по достоверности реквизитов:

- **БИН АО «Народный Банк Казахстана» (Halyk Bank) указан неверно** — в
  образце `941240001151`, что не совпадает ни с одним публичным источником.
  Правильный БИН — **940140000385** (источники: pk.uchet.kz/search/bin/940140000385,
  guide.kaspi.kz — нет, это Kaspi; сверено по tenderplus.kz, statsnet.co,
  ba.prg.kz — все сходятся на 940140000385). Используй именно это значение.
- БИН Kaspi Bank в этом же образце (`971240001315`) — сверен и подтверждён
  верным (guide.kaspi.kz/cdn/.../Rekvizity-AO-Kaspi-Bank.pdf).
- Колонка «КПН» в шапке таблицы сотрудников — вероятно, опечатка (правильная
  аббревиатура — «КНП», код назначения платежа); в тексте письма («Назначение
  платежа: ...КНП 332») используется корректное написание. Используй «КНП» в
  шапке таблицы тоже, не копируй опечатку.
- Написание «Расчетный счет» без «ё» — орфографический вариант оригинала,
  не структурная ошибка; можно использовать корректное «Расчётный счёт», это
  не противоречит требованию сохранить форматирование (шрифты/кегли/жирность),
  только не типографские опечатки.

Правило на будущее: реквизиты в любом реальном письме коллег бери с проверкой
через открытые источники (уже установленная практика в этом скилле — см.
`references/shared/fund-payer-details.md`), даже если письмо в остальном служит эталоном
оформления.
